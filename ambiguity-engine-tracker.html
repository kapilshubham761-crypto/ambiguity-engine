01 — Philosophy

Ambiguity is signal, not error.

Every standard language model is trained to do one thing well: pick the next most-probable token. When the input is ambiguous — when two interpretations are equally live, when concepts pull in opposing directions, when the territory is genuinely uncertain — the model still picks. It commits. It flattens. This is where hallucinations come from: confident wrong answers produced exactly where the model should have hesitated.

This project assumes a different stance: that ambiguity is the moment cognition actually starts. When the topology of meaning becomes unstable, the system should slow down, hold the tension, and explore — not collapse into the most popular interpretation. The whole engine is built around detecting that instability and using it as a trigger.

"Intelligence is not stored truth. It is the stabilization of unstable relational geometry into coherent structure."
BET / 01
Tension as trigger
Detect semantic conflict before generation, not after. Use it to switch the model from fast pattern-matching into slower exploration — only when needed.
BET / 02
A graph that remembers
Concepts and their relationships persist across runs. Meanings drift, edges decay, useful structures reinforce. Legible, not buried in weights.
BET / 03
Modulation, not replacement
Don't fight the transformer. Shape what it flows toward — through prompt-level modulation signals derived from the graph's current state.
02 — Working

The pipeline, at a glance.

→USER INPUTa question, prompt, or fragment of text
→CONCEPT EXTRACTIONnoun chunks + entities, embedded into vector space
→GRAPH UPDATEnew nodes added, edges reinforced or created
→AMBIGUITY DETECTIONmeasure tension across the input's concepts
→MODULATION SIGNALlow / medium / high — shapes the system prompt
→LLM CALLQwen 2.5 3B, locally via Ollama
→OUTPUT + LOGSevery decision recorded for later study
Part 01
Concept Extractor
spaCy noun chunks + MiniLM embeddings. Pulls 5–15 concepts per input and gives them vectors in 384-dimensional space.
Part 02
Semantic Graph
NetworkX in memory, SQLite on disk. Nodes hold concept text + embeddings, edges hold weighted relationships that evolve.
Part 03
Ambiguity Detector
Measures variance and cluster-split across the input's concepts in vector space. Outputs a single score from 0 to 1.
Part 04
Modulation Layer
Builds the system prompt for the LLM based on the ambiguity score and the most relevant graph neighbors. The steering wheel.

Out of scope for v0.1

  • Multi-agent cognitive fields — single engine first, see how it behaves
  • Emotional weight systems — interesting, but adds a dimension before we understand the first one
  • Autonomous cognitive loops — manual runs only; the goal is observation, not automation
  • Replacing the transformer with anything — modulation only, full stop
  • Production-grade performance — runs locally, latency is fine

03 — Build Plan

Branched, in order.

PHASE 01
Foundation
13 steps

Get a local LLM speaking to a Python script. Nothing clever yet — just the floor we'll build everything else on.

1.1Local LLM running
1.1aInstall Ollama from ollama.com and verify it runs
1.1bPull the model: ollama pull qwen2.5:3b-instruct
1.1cTest from terminal: curl localhost:11434/api/generate with a prompt
1.2Python environment
1.2aPython 3.11 venv created, activated
1.2bInstall: sentence-transformers spacy networkx pyyaml requests streamlit
1.2cDownload spaCy model: python -m spacy download en_core_web_sm
1.3Project scaffolding
1.3aFolder structure: src/ data/ logs/ snapshots/ ui/
1.3bConfig file config.yaml with thresholds, paths, model name
1.3cSmoke test: Python sends prompt to Ollama, prints response
1.3dLogging setup — every run writes to a dated log file in logs/
PHASE 02
Concept Extraction
10 steps

Turn raw text into a clean list of concepts, each one carrying an embedding vector. This is the atom of everything that follows.

2.1Extractor function
2.1aPull spaCy noun chunks from input text
2.1bAdd named entities (people, places, orgs)
2.1cNormalize: lowercase, lemmatize, strip stopwords
2.1dFilter overly generic terms ("thing", "way", "people")
2.2Embedding pipeline
2.2aLoad sentence-transformers/all-MiniLM-L6-v2
2.2bGenerate 384-dim embeddings for each concept
2.2cIn-memory cache so we don't re-embed seen concepts
2.3Eyeball validation across input types
PHASE 03
Graph Construction & Persistence
16 steps

The persistent semantic graph. Concepts become nodes, similarity becomes edges, and the whole thing survives across runs.

3.1Schemas
3.1aNode fields: id, text, embedding, first_seen, last_seen, activation_count
3.1bEdge fields: source, target, weight, edge_type, last_updated
3.2Add nodes from input
3.2aMatch new concept against existing — string equality first, then embedding similarity > 0.85
3.2bIf match: increment activation_count, update last_seen
3.2cIf no match: create new node
3.3Add and reinforce edges
3.3aCosine similarity between all new concepts and recent neighbors
3.3bThreshold for creating new edge — start at 0.5, tune later
3.3cExisting edges: increment weight on re-co-occurrence
3.4Persistence layer
3.4aSQLite schema for nodes and edges
3.4bSave graph after every run; load on startup
3.4cJSON snapshot per day in snapshots/ for time-series replay
3.4dRound-trip test: 5 inputs → restart → verify graph state intact
PHASE 04
Ambiguity Detection
11 steps

The heart. A single score from 0 to 1 that says how much semantic tension the current input contains. Everything downstream depends on this number being meaningful.

4.1Metrics
4.1aVariance metric — pairwise distances of input concept embeddings
4.1bCluster metric — k=2 means, distance between centroids
4.1cGraph-bridge metric — do input concepts pull toward disconnected regions?
4.1dCombine into one normalized score [0, 1] with tunable weights
4.2Calibration
4.2aRun on 10 technical inputs — expect scores below 0.3
4.2bRun on 10 poetic inputs — expect scores above 0.5
4.2cRun on hand-crafted tension prompts (e.g. "futuristic but warm") — expect high
4.2dLock thresholds: low < 0.3, medium 0.3–0.6, high > 0.6
4.3Log every score with its input for later analysis
PHASE 05
Modulation Layer
8 steps

Where the ambiguity score becomes a behavioral change in the LLM. Three regimes, each with a different system prompt and a different amount of graph context injected.

5.1Prompt variants
5.1aLow: clean, direct system prompt — answer normally
5.1bMedium: inject 3–5 related graph neighbors as context
5.1cHigh: explicit tension framing — "these concepts pull in different directions, explore the bridge first"
5.2Graph neighbor retrieval
5.2aFor each input concept, pull top-k highest-weighted graph neighbors
5.2bDeduplicate, rank by combined edge weight
5.3A/B logging — run same input with and without modulation; store both outputs side-by-side
PHASE 06
Decay & Pruning
6 steps

Without cleaning, the graph turns into noise. Edges fade if unused, weak ones get pruned, orphan nodes eventually drop. Useful structures reinforce themselves.

6.1Temporal decay — edge weights ×0.99 per day untouched
6.2Weak edge pruning — drop edges below 0.1 weight
6.3Orphan node pruning — nodes with no edges after 14 days removed
6.4Reinforcement — repeated co-occurrence multiplies weight by 1.1
6.5Daily maintenance job — runs on startup, checks last-cleaned date
6.6Stress test — artificially age graph by 30 days, run cleaning, verify size drop
PHASE 07
Observability
9 steps

The research interface. Without it, this is just an LLM with extra steps — with it, you can actually study how the system thinks.

7.1Streamlit skeleton — multi-page app
7.2Page · State
7.2aCounters: total nodes, edges, average degree, last cleaned
7.2bRecent ambiguity score chart
7.2cMost-activated concepts list
7.3Page · Graph view (pyvis or plotly force-directed)
7.4Page · Runner — type a prompt, see ambiguity, modulation prompt, output
7.5Page · Timeline — flip through daily graph snapshots
7.6Page · A/B — modulated vs unmodulated outputs side-by-side, with deltas
PHASE 08
Daily Diet Experiments
10 steps

The actual research phase. Different data types each day, then read the graph and the logs and look for behavior that surprised you.

8.1Curate daily corpora — one folder per day
8.2Mon — Wikipedia articles (factual prose)
8.3Tue — Reddit / forum threads (conversational, opinion clusters)
8.4Wed — Poetry (high-ambiguity, metaphor bridges)
8.5Thu — Technical docs / papers (tight, low-ambiguity clusters)
8.6Fri — News (temporal, event-based)
8.7Sat — Your own writing / chat logs (personal signature)
8.8Sun — No new input, decay only (test the cleaning operators)
8.9Per day: snapshot graph, screenshot UI, log ambiguity distribution
8.10Weekly write-up — what surprised you, what to investigate next
